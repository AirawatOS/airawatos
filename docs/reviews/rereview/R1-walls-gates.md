## Held (attacks that failed)

**B87 default-deny egress** (from filestore = aos-svc only, and scheduler = aos-svc + aos-data-secrets):
- External DNS through Docker's embedded resolver: `getaddrinfo(example.com/google.com)` → EAI_AGAIN; a raw query to 127.0.0.11 over UDP and TCP → rcode=2 (SERVFAIL), 0 answers. No forwarding from internal-only containers, so no DNS tunnel.
- `host.docker.internal` and `gateway.docker.internal` do not resolve; cross-network service names (postgres, vault, nginx) do not resolve from filestore.
- UDP DNS to 8.8.8.8:53 and 1.1.1.1:53, TCP to 1.1.1.1:80/443, 142.250.0.0:443, 8.8.8.8:53 → `ENETUNREACH`.
- Host and VM addresses 172.17.0.1, 192.168.65.1/.2/.7/.254, LAN 192.168.1.1 → `ENETUNREACH` (only the container's own subnet route exists).
- IPv6: networks have IPv6 off; containers have only `::1`, and a connect to 2606:4700:4700::1111 → unreachable.
- ICMP: no `ping`; a raw ICMP socket (container runs as root) → `ENETUNREACH`.
- Docker socket: absent in runtime-manager, scheduler, kernel and app-host. The runtime manager cannot place containers here at all.
- nginx as a proxy: fixed `network:8090` / `app-host:8099` upstreams; `/kernel/` → 404.
- Gateways of other networks (not your own subnet) → unreachable.

**B83 gate flags**
- Missing python3 → exit 97. gateflags raising → `|| exit 97`. Missing gateflags.py under production → exit 97. All fail closed by code path; the kernel/network images get the parser only by mount.
- `FILESTORE_SHADOW` values 1/2/true/enabled/blank and `PROD`/`prod`/" Production " are covered by the existing test and were not retested.
- Fullwidth `Ｐroduction` and Turkish-İ spellings → not production in every parser, so they are consistent (no bypass in either direction).
- CRLF / trailing `\r` → production in both shell and Python.

**B85 automation `/events`** (t2.py)
- Anonymous → 401. A platform-audience scheduler token → 403 "wrong audience".
- workflow, decision, app-host, svcprobe, kernel, launcher, embed-service and provisioner cannot even mint `svc:automation` (identity 403, recorded per-principal audiences).
- A list-valued aud cannot be minted (R1-10).
- Tampered payload → bad signature. `alg:none` and `alg:HS256` (key-confusion) → "unsupported alg".
- Path variants `/events?x=1`, `/EVENTS`, `/events%2f`, `/./events` → 404. `//events` and `/events#x` normalise to `/events` but still need the token.
- PUT/DELETE/PATCH → 501; GET → 404.
- `Content-Length: 999999999` with a bad token → 403 at once (body not read before authz).
- The caller pin is tenant-qualified, and identity always sets `tenant`. A federated issuer cannot be used here because automation verifies only against the home JWKS.

**B86 Network doors** (t3.py, t4.py)
- 7 doors × {decision, app-host} × variants: trailing slash → 307 to the same gated route; `/v1//…`, uppercase, `/D;x`, `//D` → 404. `%72esolve` and `?x=1` reach the same handler and the same gate (undeclared callers still 403). GET/HEAD/PUT → 405. Undeclared callers → 403 on every door. Declared callers → 200/404.
- Services that are not list callers, presenting `svc:network` tokens at `/v1/credentials|participants|tenants|join|runtime/attestations` → 401 "bad audience" (they do not fall into user mode).
- The kernel is correctly a `/v1/tenants` service caller; decision, scheduler and svcprobe are refused.
- From outside, via nginx `/network/`: every gated list → 401 anonymously.
- Realm check: a federated issuer is pinned to its registered tenant in `authn.verify`, and `_service_caller` requires `tenant ∈ {None, localdev-operator}` plus a `user://localdev-operator/` sub, so another realm's same-named principal is refused. (A missing `tenant` claim is accepted when the sub is operator-realm, but identity always emits `tenant`: Info only.)
- `NET_DOOR_CALLERS_JSON`: malformed JSON crashes at import (fails closed); a string value becomes a set of characters, so it admits nobody; a misspelled door admits nobody. Its only risk is deliberate widening, which the prod guard does not check (folded into R1-3).
