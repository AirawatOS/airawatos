# R3: Installer, verify tooling, scheduler and runtime manager (independent re-review)

Reviewer: independent, findings only. Nothing was changed: no code, config, Vault, git or container state. I read the code and did non-destructive live probes against `airawatos-localdev` (docker exec reads, `vault list/read` using the root token inside the vault container without printing it, and reading one secret's length only).

## Areas covered
- **Installer:** `deploy/installer/install.sh` (all phases), `_keys.py`, `_split_roles.py`, `_deliver_fixture.py`, `functional_check.py` (failure paths), `deploy/local-dev/vault/entrypoint.sh`, `vault.hcl`, `prod-guard.sh` and `bootstrap-dev.sh`. I looked at secrets in argv, logs and files left behind, file modes and gitignore, root-token use and where it is stored, re-run idempotency, and failure handling.
- **Verify tooling:** `Makefile`, `verify/fresh_install.sh`, `verify/conformance_matrix.sh`, `verify/scans.py`, `verify/banned_patterns.py`, `verify/images_test.py`, `verify/listen_test.py`, `conformance/build_matrix.py`, `conformance/run.py` (runner and matrix emit), `conformance/vault_scope_test.py` and `conformance/flow_map_test.py` (vacuity paths). I also checked the live results files and the in-container `/tmp/conf`.
- **Scheduler and runtime manager:** `platform-spec/reference/scheduler.py`, `runtime_manager.py`, `components/_common/launcher.py`, `event_relay.py`, `secrets.py` `/materialize`, the compose service definitions, and the live process uid, PID 1 environment and HostConfig of the runtime-manager and scheduler.

Items the first exit review already recorded are not repeated: K4 (permanent and accumulating secret-ids, 0644 approle files), K5 (init.json root and unseal key), K6 (`.creds.json` 0644), W8 (uid 0) and B51 (in-process confinement in general). Where a finding here extends one of them, it says so.

## Checked and sound
- **Phase 14 admin scrub:** it is confirm-gated, uses `metadata delete`, verifies the result and writes a marker, and a re-install demands the current password.
- **Logs:** `fresh-install.log` contains no secret values.
- **Gitignore:** `.env`, approle `*.env`, `.creds.json`, `results/` and `init.json` are all gitignored.
- **Postgres password:** it is generated rather than literal. The installer refuses an existing volume when `.env` has no password, and the `:-` empty default fails closed for postgres init.
- **Launcher secrets:** they go through a 0600 `--env-file` that is unlinked in `finally`, never through argv.
- **AppRole secret-id:** prod-guard `unset`s `VAULT_SECRET_ID` before exec.
- **Docker socket:** no docker.sock and no privileged container in local-dev. Certified-image enforcement compares the local `.Id` with the certified digest.
- **Scheduler gates:** `/runs` and `/schedules` are gated, and installed runs go only through the runtime manager.
- **Fresh install:** `fresh_install.sh` proves 0 containers, volumes and networks by project label (the `aos-*` networks carry the label, verified live), and checks that volume creation times are later than the start.
- **Gitleaks:** it fails closed, with a self-test.
