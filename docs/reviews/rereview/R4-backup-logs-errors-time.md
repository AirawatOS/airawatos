# R4 — Backup/restore, logs, error responses, time & token expiry (independent re-review)

Reviewer: independent (R4). Findings only; no code, config, Vault, git or container state was changed.
Live stack `airawatos-localdev` probed 2026-11-08 ~15:55–16:03 UTC. Real secret values are redacted below.

Probe side effects (none persist beyond the windows given):
- Failed logins were recorded in `identity_login_fails`: `localdev-operator/admin|172.18.0.3` ×3, `localdev-network/platnone|172.22.0.11` ×2, and `nosuchuser123` ×2. All are under the threshold of 5 and expire after 900 s.
- One in-memory join code was created for `r4-probe@example.invalid`.
- A probe file I copied into the network container's /tmp was removed. The `/tmp/r1lib.py` and `/tmp/t2.py` there belong to other reviewers.

## Areas covered
1. **Backup/restore.** Checked the compose volumes, `docs/operator/RESTORE-AND-ROTATION.md`, OPERATOR-GUIDE §3 and `deploy/installer`, and looked for backup or restore scripts (there are none). Ran `docker diff` on every container to find state kept in a writable layer, listed what each volume holds, and checked how a restore depends on the identity volume and on Vault.
2. **Logs.** Read `docker logs` for all 17 `airawat-ld-*` containers. Grepped the logs for tokens, passwords, JWTs, `hvs.` tokens, emails, phone numbers and tracebacks. Read the print statements in the code. Checked the logging driver and rotation, the Vault audit devices, the kernel audit tables (contents and grants) and identity's login logging.
3. **Error responses.** Sent probes from inside `aos-svc` (via the network container) to 13 services, and from the host to the edge `127.0.0.1:8080`. Probes covered `/docs`, `/openapi.json`, `/redoc`, malformed JSON, no token, wrong audience, bad signature, garbage tokens, `alg=none`, a 30 MB body, path traversal and bad escapes. Compared the identity `/login` and `/realms/<r>/login` responses and timing for existing and non-existent users.
4. **Time and expiry.**
   - Minted a user token and read its claims.
   - Read the verifiers `tokens.py`, `network/authn.py` and `kernel/services/authn.py` (exp, nbf, iat, skew, JWKS cache).
   - Read `svc_token.py` caching, run-token lifetime, app-host sessions, identity lockout timing and the password-reset path.
   - Looked up each running service's Vault token (TTL, renewal) and checked the AppRole role config.

### What blocks Layer 1 exit (from this review)
- **R4-1**: the Vault token TTL has no renewal and no re-login, so a fresh install fails after 24 h; the runbook also claims renewal that does not exist.
- **R4-2**: the identity volume (and filestore and app-bundles) is missing from the backup set and the consistency rule.
- **R4-7 (partial)**: no Vault audit device is enabled.
- **R4-8**: no container log rotation.

R4-2, the R4-7 part and R4-8 are small config or doc fixes. R4-1 needs code (renew/re-login, or a Vault Agent) plus a net that proves a service survives its token TTL.
