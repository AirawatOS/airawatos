# F1: slice-1h independent review of the guard (B97), citizen rows (B98), join code (B109) and audit tables (B103/B112-L1)

Reviewer: independent; did not build Layer 1 and took no part in either earlier exit review. Date 2026-11-09. Live stack `airawatos-localdev`, images `manishsv/airawatos-{reference,kernel,network}:1h`.
Scope: only the four slice-1h fixes named in the brief. Findings only. No code, config, compose, Vault or git changes were made.

## Summary verdict

| Area | What holds | What breaks |
|---|---|---|
| B97 guard | The baked ENTRYPOINT runs. Unset or empty AIRAWAT_ENV, `developmentx`, `development;x`, zero-width, fullwidth and NUL variants all count as production. Every `*_SHADOW` flag is refused. `svc_gate.require` refuses shadow in-process. | B109 join code | The code is not in the response, the logs or the join page. Resend throttling survives casing and whitespace changes. | The 5-attempt limit can be raced. Requests from the public exhaust the DB pool. A pending application can be overwritten by another applicant. |

## Held (verified as holding, or already registered and not re-raised as new)

- **B97, holds:** the ENTRYPOINT `/bin/sh /opt/airawat/airawat-entrypoint.sh` is baked into kernel, network and reference images (`docker inspect`). AIRAWAT_ENV unset, empty, `developmentx`, `development;x`, `dev​`, `​dev`, `ｄｅｖ`, `Dev\x00`, `prod` and `production` are all production. `Development`, `DEV`, `dev\n` and NBSP/ideographic-space variants are development, as documented. Any `*_SHADOW` flag that is set, whatever its value, is refused (rc 97). `svc_gate.require` refuses shadow in-process when the entrypoint is overridden. `/app/gateflags.py` is present in the kernel and network images, and their ImportError fallback is production. `docker exec` and flags changed after start do not affect a running service's env.
- **B98, holds for ordinary citizens:** on 13 user-mode lists (file-shares with party/direction/status, data-requests, credentials, service/transactions, role/schema/pack/interface/store-publish requests, tenants, join → 403), two random citizens see only their own rows. A citizen cannot create a share to `citizens` ("cannot share to your own tenant"). A token cannot be forged, because claims are signature-verified. A `*-participant` tenant is treated as shared, which is more restrictive.
- **B109, holds for leakage:** the code is not in the `request-code` response, not in network logs (`grep -c` → 0), and not on the join UI page (it shows `d.error` only). The SMTP-fallback log line withholds recipient and body.
- **B103, holds:** kernel_app has SELECT,INSERT only on both audit tables, and the regression test's claim is accurate for tables.
- **Registered debt, not re-raised as new:** DEBT-B110 (IDENTITY_PASSWORD_REQUIRED default shadow, KERNEL_REQUIRE_AUTH default off and unset in local-dev, PROV/DATAPLANE_ENFORCE off, PLATFORM_AUTHORITY_MODE, SCHEMA_VALIDATE=off, kernel parses its own flags) and DEBT-B84/A31 (dead AIRAWAT_ALLOW_PASSWORDLESS). F1-3 and F1-4 are concrete demonstrations of B110. F1-1 is new: B110 lists the "--no-verify abbreviation" as a hole, but the 1h code claims to close it and the fix is only partial.
