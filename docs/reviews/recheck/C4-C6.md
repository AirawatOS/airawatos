### F-C4-3 (HIGH, L1 deploy/local-dev `restore.sh`). A failure during the switch's copy-aside makes the "rollback" destroy live data
- **Cause:**
  - `PREV_EXISTED` is built incrementally inside the copy-aside loop (`restore.sh` lines ~112–119).
  - On any error there, `rollback()` treats every volume not yet in `PREV_EXISTED` as "did not exist before (a new host)". It runs `docker volume rm -f ${P}_$v` on volumes that were never touched.
  - The volume whose copy failed *is* in `PREV_EXISTED` (it is appended before the copy). Rollback then overwrites the intact live volume with the partial `-prev-` copy.
- **Effect:** stage-then-switch is supposed to keep the previous state. Instead, a disk-full during the switch (or a non-zero exit from any `docker run`/`volume create` there) destroys every not-yet-copied volume, Vault and Postgres included, and truncates another. The operator is told the previous volumes and `.restore-prev` are kept. Disk-full is the realistic trigger: the switch needs a third copy of every volume, after the stage copy.
- **Fix:**
  - Decide `PREV_EXISTED` for **all** volumes before any change.
  - Record per volume that its `-prev-` copy completed. Rollback must only refill volumes that were actually refilled, and never remove or overwrite a live volume that was not changed.
  - Pre-check free space (stage + prev needs about 2× the live size) before `down`.
  - Print the true location of the kept state.
- **Deadline:** before Layer 2 exit (it is the condition).

### F-C4-4 (Med, L1 deploy/local-dev `restore.sh`). A signal during the switch: no rollback, no message, stack left down
- **Cause:** `_exit` reads `rc=$?`. When bash dies on SIGTERM, the EXIT trap sees the **last command's status (0)**, so `_exit` returns before the rollback.
  - Reproduced with a 6-line script on `/usr/bin/env bash` (3.2.57, macOS): `trap _exit EXIT`, `docker run … sleep 4`, then `kill -TERM` → `EXIT-TRAP rc=0`, process exit 143.
- **Effect:** a supervisor timeout, `kill`, or a closed terminal (SIGHUP) mid-switch leaves the stack down with side volumes and no instruction.
  - If the signal lands during the refill, the live volumes are half-replaced. The previous state is then only in `-prev-`, and nobody says so.
  - SIGKILL cannot be trapped at all.
- **Fix:**
  - `trap 'exit 143' TERM INT HUP`, and decide in `_exit` on `SWITCHED=1 && not completed`, not on `$?`.
  - Write a durable state marker (e.g. `.restore-prev/STATE`) before `down`. Have `restore.sh` refuse to start, or offer `--rollback`, while it exists. The runbook should name it.
- **Deadline:** before Layer 2 exit.

### F-C4-5 (Low, L1 deploy/local-dev `restore.sh`). A later restore deletes the kept rollback state it told the operator not to delete
- **Cause:** after "ROLLBACK did not complete … do not delete them", the next `restore.sh` run silently runs `docker volume rm -f $P-prev-$v` and `rm -rf .restore-prev`. Observed: the recovery restore after F-C4-3 removed `-prev-localdev_appbundles`.
- **Fix:** refuse to start while any `-prev-` volume or `.restore-prev/` exists, unless the operator passes an explicit flag.
- **Deadline:** before Layer 2 exit (together with F-C4-4).

### L-C6-2 (Low, L1 deploy/installer). `run` proves the guard in a probe process, not in the helper
A helper invoked as `env PYTHONPATH=…`, `python3 -I`, or `python3 -S` passes `run`'s check and then runs unguarded (measured: rc 0). There is one deliberate use today (Phase-15 `functional_check`).
- **Fix:** have the guard export a marker that the helper's own process must set (e.g. the guard writes `$AOS_GUARD_TOKEN` and `run` checks it after exec through a wrapper), or lint `install.sh` for these patterns.
- **Deadline:** before first production. This extends L-C6-1.
