## New findings

| ID | Sev | Finding and evidence | Layer | Deadline |
|---|---|---|---|---|
| N1 | Med | The production allow-list covers argv only. uvicorn 0.54 uses `auto_envvar_prefix="UVICORN"`, so any un-allow-listed uvicorn option can be set through the environment. Live: kernel:1i with `AIRAWAT_ENV=production -e UVICORN_RELOAD=true` started the reloader, and the guard said "no dev conveniences detected". UVICORN_APP_DIR, UVICORN_ENV_FILE (loads env after the guard has run), UVICORN_FORWARDED_ALLOW_IPS and UVICORN_ROOT_PATH work the same way. Fix: refuse any `UVICORN_*` variable in production, or run uvicorn programmatically. | L1 (guard) | before Layer 2 exit |
| N2 | Low | `TRUST_REGISTRY_TOKEN` (network/trust_wiring.py:115, "a static … token wins") is a static bearer route that the production guard does not refuse. PRODUCTION-READINESS.md allows it as a choice. Decide whether it is allowed, then either refuse it or document it as a deliberate exception. | L1 guard / network | before first production |
| N3 | Med | Vault actual-read scope misses KV-v1 mounts, non-KV engines (totp code read live), LIST-only grants, `identity/` paths other than entity/id, and sudo `sys/` reads (table 7a, cases 3–7). The KV-v1 canary also leaks. **This is why C7 fails.** Fix: read KV paths by version (`options.version`); for other engines, use `sys/capabilities-self` on `<mount>/*` and on representative paths, plus LIST on every KV directory; or assert that every policy's paths match the allow-list. | L1 (assurance net) | before Layer 2 exit (it is an exit condition) |
| N4 | Med | Image content check: pip freeze cannot see a venv, files without metadata (including an auto-executing sitecustomize/.pth that can patch the guard), or a package whose dist-info was removed. Nothing checks OS binaries or /opt/airawat (the guard, the allow-list and the renewer) by content. Only the reference image's /app is checked against git. Fix: compare a content manifest (a hash of every file outside the base layer, or `/usr/local`, `/opt/airawat` and `/app`) with a record made from git and the lock. | L1 (assurance net) | before Layer 2 exit |
| N5 | Low | `os_packages` is recorded from the built image itself (build-images.sh), so the OS check cannot catch a Dockerfile-introduced package on a rebuild. Record it from a reviewed list, or diff it against the base image. | L1 | before Layer 2 exit |
| N6 | Info | The network image's default CMD (`sh -c "if … ENSURE_DEV_TENANT …; exec uvicorn …"`) is refused in production (`shell-syntax-in-wrapper`). This fails closed, but the shipped default is not runnable in production; compose overrides it. | L1 | before first production |
