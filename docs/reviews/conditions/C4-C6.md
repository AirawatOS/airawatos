### F-C4-1 (Med, L1 deploy/local-dev). Restore does not require the complete set it will destroy and copy
- **Where:** `restore.sh` lines 30–37.
- **What it checks:** the manifest equals the archives present; the host files present equal the manifest; `.env` is somewhere in the host set.
- **What it does not check:**
  - That the manifest covers **every volume compose declares**.
  - That **every service's `approle/<role>.env`** is present.
- **Live result:** a self-consistent six-volume backup restores with rc 0 and "healthy", while one durable volume is silently emptied. A backup with no approle files passes validation and then fails after `down -v`. This is the original F4-1 ("does not require the manifest to list all 7 volumes") and F4-2 class.
- **Fix:** validate against the compose-declared volume list and the 12 roles, not against the manifest's own claims.
- **Deadline:** before Layer 2 exit. This is the condition itself.

### F-C4-2 (Med, L1 deploy/local-dev). "Test-extract" is a listing, not an extraction
- **What happens:** `tar tzf` accepts archives that `tar xzf` then fails on: case E (absolute symlink), and in the same way disk-full or an unwritable target. Archives for undeclared volumes are also accepted and created. Every such failure happens after `down -v`.
- **Fix:** extract into staging volumes, or a scratch dir, before the destroy and swap after. Also refuse links and members outside `./`, and volume names compose does not declare.
- **Deadline:** before Layer 2 exit.

### I-C4-1 (Info)
- `backup.sh` restarts a stack that was stopped before it ran. Restoring the previous state would be more faithful.
- A relative backup path gives a misleading refusal: `restore.sh C` printed "localdev_appbundles.tgz is not a readable gzip/tar archive" because docker read `C` as a volume name.
- Archives are written 0644, inside a 0700 directory.

### L-C5-1 (Low, L1 deploy/runtime). Health checks token validity, not Vault access
A token whose policy was deleted or narrowed stays "healthy" while every read is denied.
- **Fix:** have the health check confirm `token/lookup-self` policies exist, or probe one capability (`sys/capabilities-self` on the service's own path).
- **Deadline:** before first production.

### L-C5-2 (Low, L1 deploy/runtime / compose). A login-failure crash loop never shows as `unhealthy`
A service that cannot log in exits before `start_period`. Docker shows `Up Ns (health: starting)` / `Restarting`, never `unhealthy`. The failure is loud only through logs and RestartCount, so an alert keyed on `unhealthy` misses it.
- **Deadline:** before first production.

### I-C5-1 (Info)
On a token that is expired but not yet revoked, the renewer gets HTTP 400 (not 401/403), so it does not do a controlled restart. Recovery then relies on Vault later revoking the token (403). This recovered here, but the renewer's dead-token test should include 400 "lease expired" or `ttl<=0`.

### F-C6-1 (Med, L1 deploy/installer). The write guard is silently missing from every app-host helper after the app-host recreate
- **Cause:** `_hook` copies `sitecustomize.py` into `/tmp/aos-hook` of network and app-host once (install.sh:283). install.sh:496 then runs `COMPOSE up -d --force-recreate app-host`, which deletes it.
- **Helpers that then run unguarded through `XAPP`:**
  - `seed_base_os.py MODE=deliver` (504)
  - `seed_base_os.py MODE=shelf` (512), the original F4-5 step
  - the Phase-15 `_deliver_fixture.py` (977)
- **Consequences:** nothing checks that the guard is loaded, and the dev fault hook does not fire either. The slice test (`verify/installer_test.py`, `("Phase 1c", "/login")`) passes because the first `/login` in Phase 1c belongs to a network-side helper. It never exercises the shelf step it claims to cover, so it gives false confidence. A failed shelf login again exits 0 and the install reports "✓ install complete". Production skips Phase 15, so nothing later catches it.
- **Fix:**
  - Run `_hook app-host` after every recreate or restart of app-host; better, bind-mount the guard as XRUNNET does.
  - Make every helper prove the guard is active, e.g. the guard exports a marker that the wrapper checks.
  - Make the test target the shelf URL (`/realms/<tenant>/login`).
- **Deadline:** before Layer 2 exit. This is the condition itself.

### L-C6-1 (Low, L1 deploy/installer). The guard covers only `urllib.request.urlopen` in a normally started interpreter
`http.client`, subprocess `curl`/`wget`, `python3 -I`/`-S` and `os._exit(0)` bypass it (all measured, rc 0). The installer does not use these for writes today. Its non-urllib writes (vault CLI, psycopg2) are exit-code-checked. A future helper could reintroduce the class.
- **Fix:** a banned-pattern check on installer helpers.
- **Deadline:** before first production.
