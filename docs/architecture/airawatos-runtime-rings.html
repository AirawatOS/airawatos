AirawatOS · runtime architecture

A civic operating system, in rings

The kernel sits at the centre and owns the truth. Around it, runtimes execute and mediate. On the outer ring, components — the certified building blocks — never touch the kernel directly; they reach it only through a runtime, always carrying who (user token) and what (component identity), so every action is authorised and recorded.

Kernel — the trusted core Trust ring — authenticate & govern Runtimes — execute & mediate Components — certified building blocks Command (sync) Event (async)

Kernel — centre

One append-only, attributed, bitemporal fact log. It is the only writer of truth: every write carries a verifiable agent and is grant-checked, so the audit trail is the registry. Also emits an event per write.

Trust ring

Identity issues the user token; AirawatNetwork certifies components, publishes the governed vocabulary (schemas · interfaces · roles), and signs the grants the kernel verifies. Together: who you are + what you may do.

Runtimes

The processes that host and execute components and broker their I/O to the kernel — the app-host BFF, the scheduler, sandboxed driver clean-room, per-profile containers, the async event relay, and the model gateway.

Components

The certified building blocks (ADR-0022): apps, engines, drivers, models, skills/agents — and solutions, which are pinned graphs of the others. Each attaches to a runtime; none reach the kernel on its own.

How each kind of component reaches the kernel

Position on a ring shows the layer a thing lives in (dependency points inward). The exact host mapping is below.

Two lanes, one governance

Command — synchronous

A user is waiting for an answer.

  1. App posts /bridge/<verb>
  2. Runtime adds token + component id
  3. Runtime runs the engine / proxies to kernel
  4. Kernel grant-checks the write → replies

Event — asynchronous

“When X happens, do Y.”

  1. Any write emits a platform.event (durable outbox)
  2. event-relay delivers at-least-once
  3. automation matches a platform.subscription
  4. It invokes the subscriber’s verb
On the roadmap (ADR-0088/0089): today an engine’s logic is hand-written code. The next step makes a domain service a declaration — a governed rule set (decide), a workflow (orchestrate), a service spec, or custom code — all uniform members of a solution graph, dispatched through this same ring. Pub/sub becomes a declared emits/subscribes capability, visible as event edges in Solution Studio.
