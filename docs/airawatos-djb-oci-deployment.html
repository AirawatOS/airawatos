AirawatOS — Pilot Deployment for Delhi Jal Board

Single-node provisioning spec for Oracle Cloud Infrastructure (OCI)
DJB · Oracle Cloud engagement — Pilot v1 · 2026-10-09

AirawatOS runs as containerised micro-services on Docker. The pilot is a single Linux VM running Docker Compose — the same shape as the live reference deployment. Everything runs inside the OCI tenancy and an India region (full data residency); the only component that may reach outside is the optional LLM (§6), which can also be deferred. This is what to provision for the pilot.

03 Operating system & runtime

  • Oracle Linux 9 (x86-64) — OCI-native; or Ubuntu 22.04 LTS. Standard cloud image, no kernel customisation.
  • Docker Engine ≥ 24 + Docker Compose v2 on the host.
  • Images (~16 services, ≈ 4 GB total with shared layers) pulled from a private registry — we mirror them to OCI Container Registry (OCIR).

04 Database

  • PostgreSQL 16, run as a container on the VM with the dedicated data volume.
  • It is the platform's system of record — a governed, append-only, bitemporal registry (every record versioned, with provenance). Back it up (see §7).
  • Keycloak and OpenFGA keep small PostgreSQL schemas; they co-locate on the same instance for the pilot.

05 Network

  • VCN with the VM on a private subnet; a public IP / NAT only where needed.
  • Inbound: only 443 (HTTPS). No public SSH — admin via OCI Bastion.
  • TLS terminated at nginx on the VM (OCI Certificates or Let's Encrypt). One public DNS name for the portal.
  • Outbound (egress): an allow-list via NAT Gateway — needed only for the optional public-data connectors and the LLM path. If DJB uses only its own data and defers AI, egress is effectively none.

06 LLM — optional, one choice

The AI features (grounded "Ask the data", document understanding, the Studio copilot) call an LLM through an internal model-gateway. It's a thin proxy — pick one, or leave it unconfigured for phase 1 and everything else runs normally.

  • Recommended · in-tenancy  OCI Generative AI — prompts/data stay inside the OCI tenancy & region.
  • Egress  An external LLM API over the NAT allow-list — simplest; prompts leave the tenancy (needs policy sign-off).
  • Defer  Leave it off for the pilot; the rest of the platform is unaffected.

07 Backup & operations

  • PostgreSQL: scheduled pg_dump / WAL archiving to the Object Storage bucket (daily; RPO/RTO to agree with DJB).
  • File store: Object Storage bucket with versioning.
  • Monitoring: OCI Logging + basic metric alarms (CPU, disk, container health) recommended.
  • Data residency: deploy in an OCI India region (Mumbai / Hyderabad). With AI off or the in-tenancy LLM, no DJB data leaves the region.

In one line: provision one Oracle Linux 9 VM (8 OCPU / 64 GB / 256 GB block) in an India region, with a VCN (443-only inbound, NAT egress allow-list, Bastion), an Object Storage bucket, OCI Vault/KMS, OCIR, and a DNS name + TLS cert. AirawatOS deploys on it via Docker Compose. The LLM (§6) is optional.

Figures are from the live reference deployment with headroom for governed-data growth; confirm against DJB's expected data volume. AirawatOS is container-native and cloud-agnostic — this maps it onto OCI for the DJB pilot.
