Principles: (i) tokens carry identity only; (ii) authority only from recorded state; (iii) nothing implied by
tenant/membership/classification/issuer; (iv) Tenant ≠ Network; (v) no silent in-memory authoritative state;
(vi) the Kernel stays domain-blind.

## Top-ten risks (severity-ranked)

1. **Unauthenticated privileged reference endpoints** — filestore (any blob r/w), notify (forge any inbox item), scheduler `/run` (execute any installed component in any tenant via the passwordless platform-service principal), model_gateway (`/complete|/embed|/transcribe` spend money), automation/event_relay. [DEBT-B5]
2. **Fail-OPEN internal-token gates; `RUNTIME_MANAGER_INTERNAL` set in no deploy file** — secrets `/materialize` (raw secrets) + `/fetch` (secret-injecting egress proxy) and runtime-manager `/invoke` (Docker + secret materialize) skip the gate when the env is unset. [DEBT-B4, DEBT-A36]
3. **Authority derived from token role claims, pervasively** — kernel/network/app-host/identity/reference; identity stamps `roles` into the token and downstream enforces off it; revocation ineffective for the 1h token life. The single most cross-cutting violation. [DEBT-B1]
4. **`is_platform_authority` = tenant name (+ prod default `airawat`)** — network-wide super-authority from a tenant name, not a recorded grant; also the first-steward chicken-and-egg. [DEBT-B2, DEBT-A17; ADR-0122 target]
5. **Possible `run_token` leak via kernel `GET /v1/components`** (unauthenticated, returns INSTALLED values carrying `run_token`) — *verify whether serialized; if so, a bearer-secret leak.* [DEBT-B15]
6. **Production-pointing identity defaults + iss/aud enforcement off** — `ds:airawat:identity`/`airawatos` silent defaults, `IDENTITY_EXPECTED_ISS/AUD` empty, EC2 posture shadow; hardening ships inert in `local`/EC2; a standalone kernel silently assumes the prod steward/issuer. [DEBT-A5-DEBT-A8, deploy B]
7. **Passwordless login still mints in production** — identity `_PW_MODE` defaults to shadow and EC2 doesn't set it; passwordless `platform.scheduler`/`platform.steward` principals mint full-authority tokens with no secret. [DEBT-A30, DEBT-B14]
8. **Silent in-memory authoritative state** — app-host `_SESSIONS` (restart = global logout, unshardable), kernel dev-tokens + adminaudit ring, automation dedup (events re-fire). [DEBT-B10]
9. **app-host `networks-mine` fabricates authority from token+tenant** when the Trust plane is off (collapses Tenant≠Network, implies admin with no recorded state). [DEBT-B2, DEBT-A25]
10. **Embed client-asserted scope not bound to the registered client** (app registered for `profile` can get a `service:invoke` consent) + the SSRF surface (secrets `/fetch`, automation `action.url`, app-host `connect-network`). [DEBT-B12, DEBT-B16]

Runners-up: committed literal dev secrets in tracked compose [deploy B]; prod-guard local-dev-only [DEBT-A57]; EC2 hot-patches not baked (revert on recreate) [DEBT-A60]; near-total absence of tests for app-host, the reference services, embed, and `/shared/aos.js`.
